RAG (Retrieval-Augmented Generation, 검색 증강 생성)

작성 목표: 손글씨 실전 답안 적정량
핵심축: 환각억제 · Hybrid Search · Fine-tuning 비교

Ⅰ. 개요

정의: RAG는 LLM이 응답을 생성하기 전, 외부 신뢰 저장소(Vector DB 등)에서 최신·도메인 문서를 검색(Retrieval)하고 프롬프트에 증강(Augmentation)하여 근거 기반 답변을 생성(Generation)하는 아키텍처
  • 등장 배경(기존 LLM 한계): ① 학습 외 정보 생성 시 환각(Hallucination) 발생, ② 학습 시점 이후 지식 최신성 결여(Cutoff), ③ 사내 비공개 데이터 학습 시 보안 유출 위험 및 고비용 재학습 문제

Ⅲ. RAG 고도화 패러다임 및 Fine-Tuning 비교

1. RAG 아키텍처 고도화 유형

구분 핵심 기법 및 특징 적용 효과
Naive RAG 단순 고정 크기 분할 → 벡터 Top-K 검색 → LLM 생성 구현 단순하나 검색 노이즈·문맥 단절 취약
Advanced RAG 질의 재작성(Query Rewrite, HyDE) + Hybrid Search + Reranking 검색 정밀도/재현율 동시 개선 (실무 표준)
Graph / Agentic RAG Knowledge Graph 기반 다중 홉 탐색(GraphRAG) 및 자가 검증·반복 검색(Self-RAG, Agent) 복합 인과관계 추론 및 전역 문서 요약 가능

2. RAG vs Fine-Tuning 비교

비교 항목 RAG (검색 증강 생성) Fine-Tuning (미세 조정)
지식 최신성 매우 우수 (DB 문서 갱신 즉시 반영) 취약 (신규 지식마다 재학습 필요)
환각 및 출처 낮음 (원문 근거 및 출처 제시 가능) 가중치 내재화로 출처 추적 불가
핵심 강점 사실 기반 질의응답(Factuality) 도메인 어휘, 출력 형식, 추론 스타일 학습
보안 · 비용 문서 단위 권한 제어(ACL) 용이, 구축 비용 낮음 학습 데이터 유출 위험, GPU 학습 비용 높음

Ⅳ. 품질 평가, 실무 고려사항 및 기술사적 제언

  • 정량적 평가 (RAGAS 프레임워크): 검색 품질(Context Precision / Recall)과 생성 품질(Faithfulness 충실도, Answer Relevance 응답 적합성)을 분리 측정
  • 실무 한계 및 대응: ① 비정형 표/PDF 파싱 오류 → Layout-aware 파서 적용, ② 검색 지연(Latency) → 시맨틱 캐시(Semantic Cache) 도입, ③ 권한 우회 노출 → Vector DB Pre-filtering(ACL) 적용
  • 기술사적 제언: 도메인 문체·추론 패턴은 Fine-Tuning으로 내재화하고, 수시 변경되는 사실·규정 지식은 Advanced RAG로 분리 결합하는 하이브리드(RAFT) 아키텍처 및 LLMOps 기반 지속 평가 체계 구축 필요
💡 시험장 암기 팁 (두문자 요약)
  • 배경: 환·최·보 환각 억제 · 최신성(Cutoff) · 사내 보안(ACL)
  • 흐름: 전·임·하·리·증·생 전처리(Chunk) → 임베딩 → 하이브리드검색 → 리랭킹 → 증강 → 생성(Citation)
  • 평가: 컨·페·앤 Context Precision/Recall · Faithfulness · Answer Relevance
